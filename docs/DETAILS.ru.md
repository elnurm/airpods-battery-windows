# Совместимость и технические подробности

[← Назад к README](../README.ru.md)

## Совместимость

| Модель | Статус |
| --- | --- |
| AirPods Pro 3 | Получение данных проверено на одном ПК с Windows 11 |
| AirPods 1, 2, 3 | Экспериментально; нужны отзывы владельцев |
| AirPods 4 / AirPods 4 с ANC | Экспериментально; нужны отзывы владельцев |
| AirPods Pro / AirPods Pro 2 / Pro 2 USB-C | Экспериментально; нужны отзывы владельцев |
| AirPods Max, Beats и другие наушники | Не поддерживаются |

Нужны **Windows 11 x64**, .NET Framework 4.8 или новее и Bluetooth-адаптер с драйвером, поддерживающим сканирование BLE. Windows 10, ARM64 и другие ОС не проверялись. Распознавание модели не гарантирует работу с любой прошивкой и адаптером.

[Расскажите о совместимости](https://github.com/elnurm/airpods-battery-windows/issues/new?template=compatibility.yml): укажите модель, прошивку (если известна), версию Windows, работу каждого наушника и уведомления об отключении.

## Особенности работы

**Точность заряда.** Приложение читает незашифрованные сигналы Bluetooth Low Energy. Данные поступают с шагом **10%** и отображаются как приблизительные (в трее — со знаком `~`). Приложение не извлекает ключи шифрования и не предоставляет точность до 1%. Заряд футляра не отображается.

**Сигнал рядом — не подключение.** Приложение отдельно проверяет подключение выбранного устройства к Windows. При отключении заряд очищается; сигналы поблизости не восстанавливают эти значения. Windows может сообщать об отключении с задержкой, а настройки уведомлений или режим «Не беспокоить» могут скрывать всплывающее сообщение.

**Автоматический поиск.** AirPods меняют адрес BLE. Приложение ищет единственный свежий сигнал, совместимый с именем устройства Windows, наблюдает его пять секунд и запоминает модель на текущий сеанс. При поиске учитываются только сигналы с данными о заряде за последние 15 секунд. Старые адреса остаются в кеше, но не мешают выбору нового сигнала. Само отсутствие новых сигналов не очищает текущий заряд: действуют обычные правила устаревания. Если подходящих сигналов несколько, заряд очищается до появления однозначного сигнала. При смене устройства Windows модель сбрасывается. Достоверно связать сигнал с устройством Windows невозможно: даже единственный сигнал может принадлежать другой паре.



**Устаревшие данные.** Пока Windows сообщает о подключении, отсутствие сигнала означает отсутствие новых данных, а не отключение. Через 60 секунд значения становятся приглушёнными и помечаются как **Последние данные**. Подробности доступны программам экранного доступа. Через две минуты без сигнала запись удаляется, заряд очищается, а автоматический поиск продолжается.

## Решение проблем

| Проблема | Что попробовать |
| --- | --- |
| Нет устройства в верхнем списке | Сначала выполните сопряжение в Windows, затем нажмите «Поиск». |
| Наушники рядом, но показано отключение | Подключите выбранное устройство к этому ПК. Близость не означает подключение. |
| Нет сигналов с данными о заряде | Откройте футляр рядом с ПК, проверьте Bluetooth и нажмите «Поиск». |
| Заряд перестал обновляться | Проверьте время обновления, держите AirPods рядом с ПК и дождитесь автоматического обнаружения нового сигнала. |
| Нет уведомления | Проверьте настройки уведомлений Windows. Состояние отключения всё равно отображается в приложении. |
| Не работает экспериментальная модель | Отправьте отчёт о совместимости без серийных номеров и Bluetooth-адресов. |

## Сборка из исходников

На ПК с Windows 11 x64 откройте PowerShell в корне репозитория:

```powershell
./scripts/build.ps1
./scripts/test.ps1 -IncludeUi
./scripts/package.ps1
```

Используются компилятор .NET Framework и системные метаданные WinRT. При первой сборке загружаются закреплённые версии Velopack и Newtonsoft.Json с проверкой контрольных сумм. Для упаковки также загружаются локальная среда .NET и Velopack CLI в `build/dependencies`; системная установка SDK не нужна. Приложение создаётся в `build/AirPods.exe`, установщик, пакет обновления, метаданные и `SHA256SUMS.txt` — в `dist/v<версия>/`. Перед пересборкой завершите приложение. [Публикация выпусков](UPDATES.md) описана на английском.

GitHub Actions собирает приложение, запускает автоматические тесты и сохраняет артефакты сборки. Выпуски автоматически не публикуются. Для проверки Bluetooth нужны настоящий ПК и AirPods; CI не подтверждает совместимость оборудования.

## Конфиденциальность и обновления

Установленное приложение обращается к публичному API GitHub Releases при запуске и раз в 24 часа во время работы, включая предварительные выпуски с метаданными обновления Windows. Ручная проверка доступна в меню трея: **Проверить обновления**. Уведомление открывает обновление внутри приложения; загрузка и перезапуск требуют подтверждения. Автоматическое уведомление появляется один раз для каждой новой версии. **Версии на GitHub** открывает страницу для ручной загрузки установщика.

Проверки и загрузки обращаются к GitHub по HTTPS. GitHub получает IP-адрес и метаданные запроса, но не Bluetooth-адреса, названия устройств или данные о заряде. Токен авторизации не используется. Последняя версия, о которой было уведомление, сохраняется в `%LOCALAPPDATA%\AirPodsBattery\notified-version.txt`. При ошибке сети автоматическая проверка повторяется при следующей ежедневной проверке. Velopack проверяет контрольную сумму пакета до установки. Доверие основано на HTTPS и контроле этого репозитория GitHub; независимой подписи издателя и подписи Authenticode пока нет.

Сигналы Bluetooth обрабатываются локально. Данные о заряде и выбранные устройства хранятся в памяти. Режим `--diagnose` записывает счётчики пакетов и ошибки рядом с приложением, не проверяет обновления и не предназначен для записи необработанных пакетов или адресов. Сообщения об ошибках могут содержать локальные пути; проверьте журнал перед публикацией.

Выбранный язык сохраняется в `%LOCALAPPDATA%\AirPodsBattery\language.txt`. Названия моделей и устройств при смене языка не изменяются.
